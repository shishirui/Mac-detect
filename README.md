# Mac 验机助手

面向二手 Mac 收购的本地原生 macOS 应用。拷贝 `.app` 后双击运行；每轮检测独立记录，自动保存，支持 PDF、HTML、JSON 导出。当前为 **0.3.0 预览版**，不是 Apple 认证检测工具，也不能保证机器无故障。

## 运行

[下载安装包](https://github.com/shishirui/Mac-detect/releases/tag/v0.3.0)。

构建产物：`dist/Mac验机助手.app`，或解压 `dist/MacDetect-0.3.0-universal.zip`。

- 目标系统：macOS 13 或更新版本；Universal 二进制包含 arm64、x86_64。
- 无需在目标机安装 Xcode、Homebrew、Python 或其他运行依赖。
- 需要能够登录并运行应用的 macOS。不能在激活锁页面或无法启动系统时直接运行。
- GitHub **v0.3.0 发布包**使用 Developer ID Application 签名并通过 Apple 公证，已附加公证票据。首次运行仍可能出现正常的“从互联网下载的应用”确认框；无需关闭 Gatekeeper 或 SIP。Apple 公证是软件分发安全检查，不是硬件检测能力认证。
- 自行构建且未配置签名 / 公证凭据时，仍会生成 ad-hoc 本地开发包，不能把它当作已公证的发布包。
- 所有自动检测均在本机执行，无遥测、账户、上传或服务器依赖。官方说明链接会在用户点击后打开浏览器。

建议先快速筛查，再根据需要运行标准 / 深度验机，完成“人工检查”，最后导出报告。

## 当前实现

| 功能 | 实际范围 |
| --- | --- |
| 硬件配置 | 从系统读取机型、芯片、CPU 核心、内存和序列号；不保证信息未被系统篡改 |
| 磁盘健康 | `diskutil info -plist /` 基础 SMART、系统 APFS 容器容量 / 可用空间；外置启动不误判内置盘通过 |
| SSD 耐久与写入 | 内置启动盘 NVMe SMART：额定耐久消耗、累计主机写入、备用空间、复合温度、通电 / 关机 / 介质错误计数 |
| 激活锁 | 仅识别系统明确报告的启用 / 关闭值；缺失或未知不作无锁判断 |
| 企业管理 | 只读 `profiles status -type enrollment`；本机未注册不证明云端无归属 |
| 崩溃记录 | 按名称 / 修改时间筛查近 30 天内核崩溃文件，不读取日志正文；不能据此确定硬件故障 |
| 热状态 | `ProcessInfo.thermalState` 系统热压力，严重 / 临界状态停止当前负载 |
| 温度与风扇 | 只读 AppleSMC 温度通道和风扇 RPM；快速模式快照，标准 / 深度模式约每 2 秒采样，保留最低 / 最高 / 最后值与次数 |
| CPU | 最多 8 个线程，循环执行多个固定整数向量，并与独立参考值校验 |
| 内存 | 256 MiB 可分配虚拟内存，多种数据模式写入并全部读回；可能分页，不覆盖全部物理内存 |
| GPU | 默认 Metal GPU 的计算任务，每轮抽查，末轮全部读回与 CPU 参考值核对；不覆盖显示接口、全部 GPU 或视频编解码 |
| 磁盘读写 | 独占临时文件、伪随机内容、fsync 后读回并核对 SHA-256；不操作裸盘，不代表全盘检测 |
| 人工清单 | 外观、各接口、网络、蓝牙、声音、唤醒、官方诊断、激活 / 组织释放和维修状态 |
| 留档 | 自动本地保存，报告历史，PDF / HTML / JSON，资产编号及备注 |
| 交机与重置 | 本机条件识别、准备检查、打开 Apple 抹掉助理、恢复 / DFU 指引、交机包导出与导入、人工交机核验 |

快速筛查不启动 CPU、内存、GPU 或磁盘写入测试。标准模式 CPU / 内存 / GPU 各 5 分钟，磁盘最多写入 512 MiB；深度模式 CPU / 内存各 20 分钟、GPU 15 分钟，磁盘最多写入 1 GiB。时间估算另受系统调用、人工操作等影响。

每个负载任务使用独立子进程；可以取消，超时终止。检测到系统严重 / 临界热状态或内存压力事件时停止当前负载。不会绕过系统温控。内核崩溃或整机断电无法靠应用阻止。

## SSD 与散热数据的解释

- **耐久消耗不是剩余年限**：NVMe `Percentage Used` 为厂家对额定耐久消耗的估算；100% 或更高提示复核，不表示一定马上损坏。255 表示超过 254%。不将它转成整机健康分。
- **累计写入**：使用完整 128 位计数，每个 Data Unit 为 512,000 字节（向上取整）；界面显示十进制 TB，JSON 保留原始十进制整数以及换算后的字节上界。0 表示设备未上报，不显示为“零写入”。这是主机写入，非 NAND 实际写入量。
- **当前告警与历史计数分开**：关键告警、备用空间低于厂家阈值、耐久消耗达到 100%、累计介质错误提示复核；仅有通电次数、非正常关机或错误日志次数不会直接判硬件损坏。
- 按启动卷的 APFS 物理存储映射选择设备，不假定 `disk0`。本版针对通过 macOS IOKit 提供 NVMe SMART 的**单个内置启动 SSD**。SATA SSD、外置启动 / USB 桥接、多物理盘 / Fusion Drive、接口或权限不支持时明确保留为无法验证；不猜测厂商专有磨损属性，也不扫描其他磁盘冒充启动盘。
- SMC 温度保留原始键名，未知通道不标为 CPU 核心或 GPU 温度；通道可能包括聚合值。界面最高温仅来自本次成功读取的通道。过滤不支持类型、非有限数和不合理读数（当前接受大于 0 且不高于 125°C）；被过滤不表示硬件损坏。SSD 温度来自独立 NVMe 快照。
- 风扇只读取 `FNum` / `F?Ac`。已知无风扇的 M1–M4 MacBook Air 标为“不适用”；其他机型读不到风扇保留为未验证。0 RPM 可以是正常停转策略，转速读取成功不证明风扇轴承、异响或散热能力正常。
- 标准 / 深度模式在负载期间约每 2 秒采样，不保证捕捉瞬时峰值。界面显示最近采样时间，超时 / 中断不把历史数值当当前值。PDF / HTML 列出峰值最高的最多 24 个温度通道，JSON 保存全部通道的汇总统计（不保存每一帧时间序列）。
- 无需管理员提权或额外安装工具；不写 SMC、不调速、不关闭系统温控、不向裸盘写入。硬件采集在独立可终止进程内执行，读取失败不会绕过权限限制。

字段定义参考 [NVMe 1.4c SMART / Health Information Log](https://nvmexpress.org/wp-content/uploads/NVM-Express-1_4c-2021.06.28-Ratified.pdf)；SMC 协议参考及许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 交机与重置助手（0.3.0）

从侧栏进入“交机与重置”，按以下流程使用：

1. **确认当前机器**：只读识别当前 Mac 的机型、芯片、系统、内置启动状态、激活锁和企业管理。Apple 芯片识别不依赖应用运行架构；Intel 优先读取 T2 信息，另识别已知搭载 T2 的 Macmini8,1。其他未确认型号保留未知。
2. **选择目的**：快速清空交机、保留数据重装、恢复模式抹除、无法启动的双机 DFU。后三项为按机型提供的操作指引和官方链接，不自动重启或执行磁盘命令。
3. **导出交机包**：包含 PDF / HTML / JSON 报告及离线 TXT 操作单。选择 U 盘，或手动复制到另一台电脑并检查可读性；同一 Mac 上的其他内置宗卷不能代替外部备份。应用无法仅凭“导出成功”证明文件已带离机器，因此需操作人确认。
4. **进入系统入口**：快速抹除要求本机与报告的序列号、机型匹配，验机记录结束，本次会话已导出交机包，并完成所有者授权 / 备份、账户归属、外部留档、电源及外设确认，输入本机序列号末 4 位。继续前重新读取本机信息，再显示目标机器与清除范围确认框。
5. **Apple 系统界面**：仅通过 macOS 的应用打开 API 打开固定路径的 Apple 抹掉助理，不传入抹除参数、不提权、不收集密码、不自动确认。最终操作由用户在 Apple 系统界面完成。入口失败时显示系统设置手动路径。
6. **交机后记录**：重新复制运行本软件，导入交机包里的 JSON，或在另一台 Mac 上导入并记录实际观察到的设置助理、联网激活和远程管理情况。导入创建独立历史记录，不覆盖原报告、不恢复任何抹除确认。核验结果须附观察记录，操作人记录的问题会影响报告结论；抹除前的检测结果仍原样保留。

快速入口要求 Apple 芯片或已确认 T2、支持的 macOS、可识别的系统抹掉助理和内置启动盘。企业管理仍报告注册、身份缺失 / 不匹配、检测正在运行、信息过期等情况下会阻止入口。未知激活锁 / 管理信息不会显示为无锁或无归属，需原主 / 原组织核实。更改所选报告或重启软件后必须重新准备。

抹除会清除所有用户的数据、设置和应用，也包括本软件及本地报告。打开系统入口仅记录为“系统接受了打开请求”，不生成自动“抹除成功”或安全擦除证明。Apple 芯片 macOS 26+ 的维修史不明机器还应按官方说明检查未完成维修。

官方参考：[抹掉所有内容和设置](https://support.apple.com/zh-cn/102664)、[进入恢复模式](https://support.apple.com/zh-cn/102518)、[重装 macOS](https://support.apple.com/zh-cn/102655)、[DFU 修复 / 恢复](https://support.apple.com/zh-cn/108900)、[DFU 端口](https://support.apple.com/zh-cn/120694)。

## 数据与恢复

- 报告：`~/Library/Application Support/MacDetect/Reports/`（JSON，目录 0700、文件 0600）。
- 磁盘测试目录：`~/Library/Caches/MacDetect/Tests/<随机 UUID>/`，正常结束或从界面停止后删除本次临时目录。
- 如果整机断电、内核崩溃或应用被强制结束，可能残留至多本轮磁盘写入上限的临时文件，可在应用完全退出后删除上述 `Tests` 目录。报告中原“待检测 / 检测中”项目重新读取时会变为已中断。
- 自动保存位于**目标 Mac**，离开前请导出到自己的 U 盘。删除 `.app` 不会删除报告。
- 导出含完整设备序列号和操作人备注；界面默认隐藏大部分序列号。报告不是防篡改证书。
- 不自动抹盘、修复磁盘、解除账户、改变设备管理或执行自动重启。

## 构建与验证

开发环境：完整 Xcode，Swift 5.9+。

```sh
swift test
# 本机原生采集、持续采样和中断集成测试（含短时负载）：
MACDETECT_TEST_APP="$PWD/.build/debug/MacDetect" swift test
./scripts/build-app.sh
open 'dist/Mac验机助手.app'
```

仅执行只读快速筛查并输出三种报告（不会启动 GUI 或压力测试）：

```sh
'dist/Mac验机助手.app/Contents/MacOS/MacDetect' --quick-report /tmp/mac-inspection.json
```

在命令行运行与界面相同的标准验机并输出三种报告（不会启动 GUI）：

```sh
'dist/Mac验机助手.app/Contents/MacOS/MacDetect' --standard-report /tmp/mac-standard-inspection.json
```

标准验机约需 15–25 分钟，CPU / 内存 / GPU 各测试 5 分钟，磁盘最多写入 512 MiB；沿用界面的温度 / 风扇持续采样、热状态及内存压力保护。终端会提示当前检测项目。人工检查项目仍保留为未验证。

两种命令均会生成指定 JSON，以及同名 HTML、PDF。每次只选一种报告模式，并提供输出路径；缺少路径或同时指定两种模式会报错退出。实际机器序列号会写入这些本地文件，不应上传到代码仓库。

仅验证重置条件的只读命令（不会打开抹掉助理或执行重启 / 清除）：

```sh
'dist/Mac验机助手.app/Contents/MacOS/MacDetect' --reset-readiness-report /tmp/mac-reset-readiness.json
```

该 JSON 同样包含当前机器序列号，请妥善保管。没有提供命令行静默抹除开关。

正式分发构建需要 `MACDETECT_SIGN_IDENTITY`（已安装的 Developer ID Application 证书）以及以下任一认证方式：

- `MACDETECT_NOTARY_PROFILE`：已存在的 notarytool 钥匙串配置。
- `MACDETECT_NOTARY_KEY_PATH`、`MACDETECT_NOTARY_KEY_ID`：本机已有的 App Store Connect API 私钥路径与 Key ID；团队 API Key 还需 `MACDETECT_NOTARY_ISSUER_ID`，个人 API Key 不提供 issuer。

在本机安全配置这些环境变量后，执行：

```sh
MACDETECT_REQUIRE_NOTARIZATION=1 ./scripts/build-app.sh
```

构建脚本会校验 Developer ID 和安全时间戳，等待 Apple 返回 `Accepted`，附加并校验票据，通过 Gatekeeper 检查后才生成分发 ZIP。`MACDETECT_REQUIRE_NOTARIZATION=1` 会拒绝缺少签名 / 公证配置的构建。可用 `MACDETECT_OUTPUT_DIR` 指定独立输出目录，保留已发布版本。校验文件使用 ZIP 文件名，可在下载目录执行 `shasum -a 256 -c SHA256SUMS.txt`。

不要把账号、密码、证书私钥或环境变量的实际配置值提交到仓库。公证结果保存在 `.build/notarization/`，不会加入 Git。

## 验收边界

编译和单元测试不能替代真机适配。首次交付的本机验证范围见 `VALIDATION.md`。必须使用实际收购的 Mac mini、不同 macOS 和 Intel 机型继续验证，尤其是已知故障机的检出能力。目前没有完成机型覆盖认证，不应据此单独决定收购。

后续优先项：真实 Mac mini / Intel 正常与故障样本验收、SATA 厂商专有寿命属性适配、接口传输辅助、长时间稳定性统计。
